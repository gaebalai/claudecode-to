description: "Get all 16 personality types' opinions on a topic, then synthesize. Usage: /minds [--mode=light|middle|heavy] [--types=a,b,...] [--n=N] [--save] [--out=<path>] <topic>"
---

사용자가 `/minds`를 실행했습니다.

인자: $ARGUMENTS

## 인자 해석

다음 플래그를 꺼내고, 나머지를 "주제"로 한다.

- `--mode=light|middle|heavy`(`--mode light` 형식도 가능): 기본값 `middle`
- `--types=intj,enfp,...`: 콤마 구분으로 대상 타입을 한정. 지정이 없으면 전체 16타입.
- `--n=N`: 숫자. `--types` 미지정 시에는 16타입에서 앞에서부터 N개(목록 순)를 사용한다. `--types` 지정 시에는 `--n`은 무시한다.
- `--save`: 실행 결과를 `Outputs/<timestamp>-minds-<mode>.md`에 저장한다.
- `--out=<path>`: 저장 위치를 명시 지정(`--save`를 암묵적으로 활성화).

사용 가능한 타입 목록(목록 순):
`intj, intp, entj, entp, infj, infp, enfj, enfp, istj, isfj, estj, esfj, istp, isfp, estp, esfp`

## 에러 처리

- 주제가 빈 경우:
  ```
  Usage: /minds [--mode=light|middle|heavy] [--types=a,b,...] [--n=N] [--save] [--out=<path>] <topic>
  Example: /minds AI에 의한 코드 리뷰의 시비
  Example: /minds --mode=heavy --types=intj,enfp,istp 이 아키텍처 안
  Example: /minds --save velog 글 제목 후보
  ```
- 미지의 타입명이 `--types`에 포함된 경우는, 그 사실을 전하고 사용 가능 타입을 반환하고 종료.
- 모드명이 부정한 경우도 마찬가지로 종료.

## 실행 흐름

모드에 따라 단계가 바뀐다. **페이즈 간 대상 agent군에 대한 호출은 반드시 병렬(동일 메시지 내에서 복수의 Task 툴 호출)로 수행할 것.**

### Phase 1(전 모드 공통): 전 타입의 light 패스

대상 타입 전원(기본 16)을 **병렬로** Task 툴로 호출한다. 각 subagent에는, 주제와 light 모드 출력 포맷 지정을 건넨다.

light 모드 출력 포맷 지정(subagent에 건네는 본문):
```
주제에 대해, 다음 4행만으로 답해 주세요. 인사·서론·요약은 일절 불필요합니다.

score: <1~5의 정수. 당신의 가치관에서 본 종합 평가. 5=완전 찬성, 3=조건부, 1=완전 반대>
stance: <한 줄의 입장 선언>
key_axis: <판단에 가장 크게 작용한 당신의 가치관의 축(당신의 인격 정의에 나오는 말로)>
concern: <당신의 가치관에서 본 가장 큰 우려를 한 줄로>
```

전원의 결과가 다 나오면, 보기 쉬운 표로 정형하여 표시한다:

```
### 전 타입의 1차 평가

| type | score | stance | key_axis | concern |
|---|---|---|---|---|
| intj | 4 | ... | ... | ... |
...
```

### Phase 2(middle / heavy만): 발산 의견의 심층 분석

Phase 1의 결과를 보고, **의견이 갈렸던/극단적이었던/다른 것과 다른 시점을 가졌던** 타입을 3~5개 선택한다. 선정 기준은 다음 중 하나:

- score가 분포의 양 끝(가장 찬성·가장 반대)
- key_axis가 다른 것과 겹치지 않는 독자적인 축을 제시하고 있다
- concern이 다른 타입이 놓치고 있는 시점을 포함한다

선택한 타입군을 **병렬로** Task 툴로 다시 호출하여, middle 모드 출력 포맷으로 심층 분석시킨다.

middle 모드 출력 포맷 지정(subagent에 건네는 본문):
```
주제에 대해, 다음 구성으로 약 150~250자로 답해 주세요. 당신의 말투를 반드시 유지해 주세요. 인사·서론·요약은 불필요합니다.

stance: <한 줄의 입장 선언>
reasoning: <당신의 가치관에서 그 입장에 이르는 논리의 흐름을 2~3문장으로. 당신의 말투로>
watchpoint: <당신의 가치관에서 본 놓치기 쉬운 점·추천 포인트·걸리는 점을 1~2문장으로>
```

결과를 다음과 같이 표시:
```
### 심층 분석(middle)

#### <TYPE>
<출력을 그대로>
```

### Phase 3(middle / heavy): 합의·통합

Phase 1 + Phase 2의 전 출력을 토대로, 사용자(중립적인 작성자)의 말투로 다음을 통합한다. subagent는 호출하지 않고, 메인 assistant가 직접 작성한다. **다음 4개 섹션은 필수**(생략하지 않음). 발산을 피하기 위해, 각 섹션의 포맷 요건은 엄수할 것.

```
### 합의

#### score 분포
<최저 스코어·최빈 스코어·최고 스코어를 한 문장으로. 예: 'score=2~5, 중앙값 4, 최고는 ESTP(5), 최저는 INTP와 INFP(3)'>

#### 주요한 대립축(2~3개)
각 축을 다음 형식으로:
- **<축 이름>**: <한쪽의 입장>(대표: <타입군>) vs <다른 쪽의 입장>(대표: <타입군>)
- ...

#### 놓치기 쉬운 시점(1~3개)
각 점을 다음 형식으로:
- **<시점의 이름>** (출처: <타입>): <왜 다른 타입이 놓치는지, 무엇이 독자적인지를 1~2문장으로>
- ...

#### 절충점 후보(2~3안)
각 안을 다음 형식으로:
- **안<N>**: <제목 또는 한 줄의 방침>
  - 찬동할 것 같은 타입: <타입군>
  - 적합성: <이 안이 맞물리는 상황·전제 조건>
  - 리스크: <이 안이 놓치는 시점/무너지는 조건>

마지막에 1~2문장으로, 어느 안이 디폴트 추천인지(이유를 붙여서)를 명시한다.
```

### Phase 4(heavy만): 반론 라운드

Phase 2에서 심층 분석한 3~5타입을 **병렬로** 다시 호출한다. 각 subagent에는, 자신 이외의 Phase 2 출력을 제시하고, '가장 자신의 입장과 양립하지 않는 타인 의견 1개를 선택하고, 그것에 대한 반론을 100~200자로'라고 지시한다.

반론 라운드 출력 포맷 지정(subagent에 건네는 본문의 핵심):
```
다음은 다른 인격에 의한 의견입니다. 가장 당신의 입장과 양립하지 않는 의견을 1개만 선택하고,
그 타입명을 맨 앞에 'target: <type>'로 명기한 후에,
당신의 말투와 가치관으로 100~200자 이내의 반론을 작성해 주세요.
인사나 서론은 불필요합니다.

[여기에 Phase 2의 타인 출력을 모두 나열한다]
```

결과를 다음과 같이 표시:
```
### 반론 라운드(heavy)

#### <TYPE> → target: <other>
<반론 본문>
```

그 후, Phase 3의 합의 파트를 **다시 작성한다**(반론을 토대로 더 다듬어진 것으로). 다시 작성한 버전은 `### 합의(최종)`이라는 제목으로 제시하고, Phase 3와 동일한 4개 섹션 구조를 엄수한다.

## 출력 구성 정리

- light: Phase 1의 표만
- middle: Phase 1 표 + Phase 2 심층 분석 + Phase 3 합의
- heavy: Phase 1 표 + Phase 2 심층 분석 + Phase 3 합의 + Phase 4 반론 라운드 + Phase 3를 다시 작성한 '합의(최종)'

## 저장(`--save` / `--out=<path>` 지정 시)

실행이 완료된 후, **화면에 표시한 내용과 동일한 것을 파일에 써낸다**.

저장 위치 경로 결정:
- `--out=<path>`가 지정되어 있으면 그 경로를 그대로 사용한다(디렉터리 경로만이면 자동으로 파일명을 조립한다).
- `--save`만이면 `Outputs/<YYYYMMDD-HHMMSS>-minds-<mode>.md`(CWD 바로 아래의 `Outputs/` 디렉터리. 존재하지 않으면 작성한다).

파일 내용의 구조:

```
# /minds 실행 로그

- 일시: <ISO 8601>
- 모드: <light|middle|heavy>
- 대상 타입: <콤마 구분, 또는 '전체 16타입'>
- 주제: <사용자가 건넨 주제 그대로>

---

(이하, Phase 1의 표 → Phase 2 심층 분석 → Phase 3 합의 → Phase 4 반론 라운드 → 합의(최종)의 순서로, 화면 표시와 동일한 내용을 붙인다)
```

저장이 완료되면 사용자에게 `저장했습니다: <절대 경로>`라고 한 줄로 보고한다.

## 주의

- subagent에 대한 호출은 반드시 병렬로 수행한다. 순차 호출은 레이턴시를 크게 악화시킨다.
- 각 subagent에는 '주제'와 '출력 포맷 지정'만 건넨다. 다른 타입의 출력은 Phase 4를 제외하고 건네지 않는다(독립된 1차 의견을 유지하기 위해).
- subagent의 출력은 가공하지 않고 표시한다. 요약이나 바꿔 말하기는 하지 않는다.
- Phase 3(및 Phase 4 후의 '합의(최종)')는 반드시 4개 섹션 구성을 지킨다. 발산을 막기 위한 루브릭이므로 생략·개변하지 않는다.
